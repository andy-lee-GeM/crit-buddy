# Cylinder Array Request Template

This template provides the standard structure for cylinder-array criticality analyses following the CB-11/CB-12 format.

## Directory Structure

```
requests/CB-XX/
├── CB-XX-summary.md          # Visual summary (use template below)
├── configs/
│   ├── 01_uf6_dry.yaml
│   ├── 02_hu_opt.yaml
│   ├── 03_wet_bottom_fill.yaml
│   └── 04_uo2f2_bounding.yaml
├── runs/                      # Generated by runner
├── results/                   # Generated by runner
├── all_results.csv           # Generated results aggregation
├── bounding_analysis.json    # Generated bounding calculation
└── experiment-plan.md        # Optional planning document
```

## Config Template: 01_uf6_dry.yaml

```yaml
  enrichment_pct: 21.0
  fissile_density_g_cm3: 5.09  # solid UF6

  water_film_thickness_cm: 0.0  # dry case
  wall_thickness_cm: [0.3175, 0.635]  # sweep wall thickness

  # Array geometry

  num_cylinders_y: 1
  num_cylinders_z: 1
  wall_to_wall_gap_cm: [1, 2, 5, 10, 20, 30]  # sweep gap

  # Boundary conditions

  y_boundary_type: vacuum
  z_boundary_type: vacuum
```

```markdown
## Safety Margin Analysis

| Category | Metric | Symbol / Equation | Value | Units | Source |
|---|---|---|---:|---|---|
| Criticality limit | Critical fill threshold | `f_crit` | 0.20 | fraction | Wet-UO2F2 sweep |
| Criticality limit | Peak moderation | `H/U_peak` | 30.0 | - | H/U sweep |
| Criticality limit | Cylinder capacity | `V_total` | 51430.81 | cm3 | Geometry/config |
| Criticality limit | Limit wet UO2F2 mass | `M_crit = f_crit * V_total * rho(H/U_peak) / 1000` | 18.670 | kg | Computed |
| Bounding basis | Leak rate | `dP/dt` | 0.01 | torr/min | Assumption |
| Bounding basis | Lifetime | `t_life` | 30.0 | years | Assumption |
| Bounding basis | Gas-volume basis policy | `V_gas = V_total/1000` | DEFAULT (void_volume_liters omitted) | - | Standard default |
| Bounding basis | Gas volume used | `V_gas` | 51.431 | L | Config/default |
| Bounding basis | Fixed environment basis | `100% RH @ 25 C` | 100% RH @ 25 C | - | Method assumption |
| Bounding result | Total water ingress | `n_H2O = ((dP/dt*x_H2O)*t_min/760) * V_gas/(R*T)` | 13.658 | mol | Computed |
| Bounding result | Lifetime wet UO2F2 mass | `M_bound = (n_H2O/2) * MW_wet(H/U_peak) / 1000` | 3.949 | kg | Computed |
| Comparison | Safety margin | `SM = M_crit / M_bound` | 4.728 | x | Computed |
| Comparison | Time to limit | `t_limit = t_life * SM` | 141.836 | years | Computed |
| Decision | Criticality concern? | `M_bound >= M_crit` | NO | - | Decision rule |

Decision rule: `NO concern` if `SM > 1` (equivalently `M_bound < M_crit`).
```

## Notes

### Key Differences from CB-11/CB-12

1. **Config format**: Uses `model: cylinder-array` with `params:` instead of legacy `problem: cascade_array`
2. **Parameter names**: Updated to match the cylinder-array model specification:
   - `R_inner_cm` → `inner_radius_cm`
   - `H_inner_cm` → `vessel_height_cm`
   - `t_wall_cm` → `wall_thickness_cm`
   - `i/j/k` → `num_cylinders_x/y/z`
   - `gap_xy_cm` / `gap_z_cm` → `wall_to_wall_gap_cm`
   - `reflector_thickness_cm` → `edge_moderator_thickness_cm`

### Standard Workflow

1. **01_uf6_dry**: Screen UF6 dry fill conditions across gap and wall thickness
2. **02_hu_opt**: Find peak H/U moderation for UO2F2 using worst-case geometry from 01
3. **03_wet_bottom_fill**: Generate 2D heatmap of fill fraction vs gap at peak H/U
4. **04_uo2f2_bounding**: Single bounding case with reflective boundaries

### Safety Margin Table

The table format follows CB-11/CB-12 structure:
- **Criticality limit**: Values defining the critical mass threshold
- **Bounding basis**: Assumptions used for water ingress calculation
- **Bounding result**: Computed water accumulation and resulting UO2F2 mass
- **Comparison**: Safety margin and time-to-limit calculations
- **Decision**: Binary criticality concern determination

All equations should be shown inline using backticks for traceability.

## Usage

1. Create new request directory: `requests/CB-XX/`
2. Copy config templates to `configs/` and customize for ticket
3. Run studies using crit-buddy runner
4. Generate summary using CB-XX-summary.md template
5. Update paths and values based on actual results
